# Custom Wazuh SIEM Detection Engineering for pfSense

## Overview
This repository contains custom decoders and detection rules engineered for a Wazuh SIEM environment. The goal of this project was to resolve default parsing failures and aggressive rule hijacking when ingesting pfSense firewall telemetry.

## The Problem
When forwarding `filterlog` (firewall drops) and WebGUI authentication logs from pfSense to Wazuh, the default `OS_Regex` decoders failed to parse the logs correctly:
1. **Rule Hijacking:** WebGUI failed logins were incorrectly categorized under generic `FreePBX` rules, masking brute-force attempts.
2. **Missing Hostnames:** pfSense omitted its hostname in specific syslog headers, causing Wazuh to misalign the log string and fail the decoding phase entirely.
3. **Format Variations:** Internal LAN ICMP/TCP drops were formatted differently than external WAN drops, causing silent pipeline failures.

## The Solution
To establish complete visibility over the network edge, I engineered custom XML configurations bypassing the default engine constraints:

* **Custom PCRE2 Decoders (`local_decoder.xml`):** Upgraded the parsing logic to utilize the PCRE2 engine, allowing the SIEM to accurately strip leading whitespace and parse the non-standard `[0-9]+,,,` strings generated by pfSense LAN interfaces.
* **Rule Overrides (`local_rules.xml`):** Authored Level 5 and Level 8 rules to explicitly intercept logs hijacked by the FreePBX rule group (`<if_sid>70000</if_sid>`).
* **MITRE ATT&CK Mapping:** Mapped WebGUI authentication failures directly to MITRE Technique T1110 (Brute Force / Credential Access) to enrich SOC dashboard visibility.

## Validation
The detection pipeline was validated end-to-end by intentionally generating dropped TCP/ICMP traffic and failed authentication attempts across internal VLANs, confirming successful alert generation within the `wazuh-alerts-*` index.
